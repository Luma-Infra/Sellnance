## 1. 모바일 새로고침 시 티커 로고 폴백(사슴) 노출 버그 개선

### 문제 원인

1. **비동기 초기화 갭**: 새로고침 즉시 라우터가 코인 헤더(`selectSymbol`)를 렌더링할 때, 전체 테이블 데이터(`store.currentTableData`)가 아직 서버 응답을 대기 중이라 `rowInfo`가 `null`로 평가됨.
2. **보조 API 로고 누락**: `rowInfo`가 없을 때 호출되는 보조 API(`/api/coin-info`) 응답에 로고 필드가 빠져 있어, 응답 수신 시 헤더에 기본 사슴 로고를 강제 주입함.
3. **지연 로딩 정책**: 상단 헤더 이미지에 `loading="lazy"`가 걸려 있어 모바일 환경에서 렌더링이 지연되고 깜빡임이 두드러짐.

### 조치 내역

- **프론트엔드 캐시 선제 동기화**: `static/main_init.js` 초기 구동 시 `preloadCachedMarketData()`를 동기 실행하여 로컬 스토리지에 캐시된 장부와 코인 로고를 0초 시점에 스토어(`store.tickerRowMap`)에 즉시 적재.
- **백엔드 API 로고 필드 추가**: `modules/app.py`의 `/api/coin-info/{asset}` 응답 객체에 `logo: coin.get("Logo", "")` 필드를 포함하여 보조 조회 시에도 원본 CMC 로고가 반환되도록 수정.
- **헤더 렌더링 최적화**: `static/ui_selection.js`에서 헤더 로고 렌더링 시 `loading="eager"` 및 `decoding="async"`를 적용하고, 수신된 로고를 우선 반영하여 사슴 폴백 노출을 차단.

## 2. Go 마이그레이션: SoA 기반 Branchless 빌더 설계 (builder.go)

### 설계 목적

- 기존 파이썬 `builder.py`에 누적된 거래소 종속 순차 루프와 다중 if 분기를 단순화.
- 고빈도 시세 수신 시 CPU 캐시 효율과 연산 속도를 높이기 위한 구조체 배열(SoA) 구조 도입.

### 주요 아키텍처

1. **SoA (Structure of Arrays) 메모리 구조**:
   - 코인별 구조체 배열(`[]CoinRow`) 대신 거래소별 가격 평면 배열(`[MaxCoinSlots]float64`)로 배치하여 연속 메모리 L1/L2 캐시 적중률 유지.
2. **Branchless 산술 연산**:
   - 김치프리미엄 및 베이시스 계산 시 if 조건 분기 대신 CMOV / 비트마스크 연산(`selectNonZero`, `float64FromBool`)을 적용하여 CPU 분기 예측 패널티 감소.
3. **이벤트 기반 단일 슬롯 갱신**:
   - 전체 코인을 순회하는 대신, 거래소 틱 수신 시 `UpdatePriceAndKimchiDirect(slot, market, price)`를 통해 해당 슬롯만 단일 산술식으로 즉시 갱신.
4. **무설정 자가치유 (Self-Healing)**:
   - `mapping.json`이 유실되거나 손상되어도 거래소 API 데이터만으로 슬롯을 구성하여 기본 동작이 유지되도록 설계.
